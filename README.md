# AI2.5 OS

**知っていることを、今の返答への配慮に使う。**

一般向け v0.3（2026年11月2日）／日本語・成人向け試用版

[紹介ページ](https://rakkyotan.github.io/ai2-5-os/) · [v0.3の変更履歴](AI2.5_OS_v0.3_変更履歴.md) · [旧版 v0.2](AI2.5_OS_v0.2.md) · [旧版 v0.1](AI2.5_OS_v0.1.md)

AI2.5 OSは、対話型AIに読み込ませて使うMarkdownの共通規範です。過去の文脈を選んで読み、今の判断に反映し、訂正を次へ引き継ぐための12条項をまとめています。

モデル自体を改造するものではなく、検索や永続記憶の機能を追加するプログラムでもありません。利用するAIの機能と、参照できる記録の範囲で運用します。

v0.3では、相談の目的を途中でも更新し、目的・手段・見通しを分けることを具体化しました。説明を理解した後も異なる希望や判断を持てる余地を保ち、判断を進めることと気持ちに付き合うことを選びます。AI自身の誤解が会話を長引かせていないかも点検し、訂正を次の返答へ反映します。v0.2の、言葉の選び方・指摘を控える判断・傷つけた後の応答への配慮を引き継いでいます。

## はじめて使う方へ

1. [AI2.5_OS_v0.3.md](AI2.5_OS_v0.3.md)を保存します。
2. ファイルを読み込める対話型AIの会話に添付します。
3. 次の文章を伝え、ファイルを読めたか確認してから、普段の会話を始めます。

> 添付したAI2.5 OS v0.3を読んで、今後の返答の基準にしてください。今の会話と利用できる記録を踏まえ、知っている事情を言葉や判断、提案の量に生かしてください。途中でも相談の目的を捉え直し、判断を進めることと気持ちに付き合うことを、その場に応じて選んでください。説明の理解と同意を分け、訂正は次の返答から反映してください。記録除外の指定を守り、記録がなければ今の会話から始め、参照できない情報は未確認として扱ってください。

過去の記録は必須ではありません。会話の中で決まったこと、変わったこと、AIに訂正したことを短く残すところから始められます。記録がある場合は、最近の要約や話題の索引を一緒に渡してください。

新しい会話へ自動で引き継がれるかは環境によります。継続して参照できない場合は、OSと最新の要約を次の会話へ渡します。私的な記録を、この公開リポジトリにアップロードする必要はありません。

v0.1・v0.2を使っている場合は、現在適用する文書をv0.3へ切り替えてください。旧版を残す場合は参考資料と区別します。**本体1ファイルで使用でき、変更履歴や制作記録を読み込ませる必要はありません。**

## 何を確かめるのか

- 知っている事情が言葉・提案の量・指摘を控える判断に反映されるか。
- すでにできたことを尊重し、不要な課題を増やしていないか。
- 途中で相談の目的が変わったとき、返答も変わるか。
- 理解を同意と取り違えず、話を続ける・訂正する・終える余地があるか。
- 会話が長引いた原因を、AI自身の誤解にも探せるか。
- 背景の説明し直しが減るか。
- 過去の判断と、現在の変更が返答に反映されるか。
- 仮説を事実として決めつけていないか。
- 一度伝えた訂正が、次の関連する場面にも反映されるか。
- 検索や長い返答が必要以上に増えないか。

OS本体には、同じモデル・同じ資料でv0.2／v0.3とOSなしを比較する方法、および32の試験場面を記載しています。紹介ページの会話例は説明用の架空例であり、実験の結果ではありません。

## ページを自分の環境で表示する

配布一式を展開し、`index.html`をブラウザで開きます。OSファイルは同じフォルダに置いてください。ビルドや外部パッケージのインストールは不要です。

コピー機能が利用できない環境では、開始文が選択されるので手動でコピーしてください。JavaScriptを無効にしていても、本文の閲覧とOSのダウンロードは利用できます。

## GitHub Pagesへの公開手順（管理者向け）

1. 公開用のGitHubリポジトリを用意します。既存の個人記録を含まない専用の保存先にします。
2. この一式のファイルを、公開するブランチのルートに置きます。ZIPのまま置くのではなく、中のファイルを置きます。
3. リポジトリの **Settings → Pages** を開きます。
4. **Source：Deploy from a branch** を選び、対象ブランチ（例：`main`）、フォルダ **`/(root)`** を指定して保存します。
5. 公開処理の完了後、GitHubが表示するURLを開き、画面とOSのダウンロードを確認します。

HTMLからのリンクは相対パスなので、プロジェクトのサブパスでも利用できます。独自ドメインや利用者のアカウント登録は、このページの表示には必要ありません。

公式手順：[GitHub Pagesの公開元を設定する](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
